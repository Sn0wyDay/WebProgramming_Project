# RE:VERSE — 가벼운 로컬 팀프로젝트

이번 담당 범위는 **홈과 곡 상세·가사 작성**입니다. UI는 API 연결 이전 커밋 `87e9b7c`를 기준으로 복원했습니다.
팀 통합 방법과 API 안정성 조사 결과는 [홈 담당 인수인계](docs/HOME_HANDOFF.md)에 정리했습니다.

Flask 하나에서 HTML/CSS/JavaScript 화면과 JSON API를 함께 제공합니다.
DB는 Python에 포함된 SQLite를 사용하므로 MySQL·Docker 설치가 필요 없습니다.

## 더블클릭 실행 (Mac)

`REVERSE 실행.command`를 더블클릭하면 필요한 환경을 준비하고 브라우저를 엽니다.
이미 RE:VERSE 서버가 실행 중이면 재사용하므로 중복으로 켜지지 않습니다.
Python 3.9 이상이 필요하며, 첫 라이브러리 설치와 외부 음악 검색에는 인터넷이 필요합니다.
내부적으로 로컬 Flask 서버가 동작합니다. 새 서버를 켠 경우 실행 창을 열어 두고 사용하세요.
종료는 실행 창에서 Ctrl+C를 누릅니다. `index.html`만 열면 API 기능은 동작하지 않습니다.
프로젝트 폴더 전체를 함께 보관해야 합니다.

## 명령으로 실행

Python 3.9 이상에서 저장소 폴더를 열고 실행합니다.

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

Windows에서는 가상환경 활성화 명령을 `.venv\Scripts\activate`로 바꿉니다.
[실행 화면](http://127.0.0.1:5001)에 접속합니다.
처음 실행할 때 DB와 세션 키를 생성하고, 실행할 때마다 필요한 마이그레이션을 적용합니다.
`.env` 작성이나 API 키 입력 없이 실행할 수 있습니다. 옵션 예시는 `.env.example`에 있습니다.

## 로컬 저장

- `instance/preview.db`: 계정, 코멘트, 별점, 저장한 곡, 친구 관계, 로그인 세션
- `instance/provider-cache.sqlite3`: 공개 API 응답·가수 별칭·호출 대기 상태
- `instance/.secret-key`: 서버 재시작 후에도 유지하는 로컬 세션 키
- `instance/` 전체는 Git에서 제외됩니다. DB 파일을 지우면 기록이 사라집니다.
- 신규 계정은 빈 상태로 시작합니다. 기존 가상 곡이나 친구를 자동 등록하지 않습니다.
- 다른 브라우저에서도 같은 서버에 접속하면 서로 다른 계정으로 요청·수락할 수 있습니다.
- 비밀번호는 해시로 저장하며 8~128자입니다. CSRF와 서버 권한 검사는 유지합니다.

- 회원가입·로그인·로그아웃·프로필 수정

- 외부 MusicBrainz 곡·가수 검색, 곡 선택 후 중복 없이 DB 저장
- LRCLIB 실제 가사 조회·구절 저장, 내부 출처 정보 보관
- 로컬 DB 곡명·가수명·확보한 가사 검색, 곡 상세
- 구절 코멘트 작성·수정·삭제, 나만 보기·친구 공개 권한
- 저장 직후와 새로고침 후 코멘트를 작성한 가사 구절 바로 아래에 표시
- 가사 버전이 바뀐 코멘트는 당시 구절과 함께 별도 보관
- 계정별 별점·음악 기록·곡 저장, 기록 검색
- 실제 곡·앨범 평론 자동 조회, 평론가·짧은 발췌·원문 링크 표시
- 불변 가사 버전·구절 및 곡·평론 관계 모델, Alembic 마이그레이션

## 음악·가사 연결

별도 가입·키 없이 Flask에서 공개 API를 호출합니다. 의존성은 requirements.txt로 설치합니다.

| 역할 | 오픈소스 및 문서 |
| --- | --- |
| 곡·가수·앨범 정보 | [MusicBrainz 서버](https://github.com/metabrainz/musicbrainz-server), [API](https://musicbrainz.org/doc/MusicBrainz_API) |
| 실제 가사 | [LRCLIB 서버](https://github.com/tranxuanthang/lrclib), [API](https://lrclib.net/docs) |
| 앨범 표지 | [Cover Art Archive 오픈소스](https://github.com/metabrainz/artwork-redirect), [API](https://musicbrainz.org/doc/Cover_Art_Archive/API) |
| 음악 평론 | [IZM 공개 리뷰](https://www.izm.co.kr/), [Beautiful Soup 오픈소스 파서](https://www.crummy.com/software/BeautifulSoup/) |
| 연말 선정 기사 | [HELLOKPOP 연말 결산](https://www.hellokpop.com/review/2025-in-review-day-3-the-honorable-mentions/), [WordPress 공개 API](https://developer.wordpress.org/rest-api/reference/posts/) |

홈의 **추가** 버튼을 눌러 검색 모달을 열고, **외부 음악**에서 곡명·가수명을 검색한 뒤 결과를 선택합니다.
서버가 MusicBrainz ID와 서버에서 확보한 메타데이터를 기준으로 SQLite에 저장합니다.
가사는 LRCLIB에서 곡명·가수·가능한 경우 재생시간을 대조합니다.
외부 검색은 20개씩 이전·다음 페이지로 탐색할 수 있습니다.
**저장된 음악·가사**로 범위를 바꾸면 이미 확보한 자료의 키워드를 검색합니다.

등록된 가사가 없는 곡이나 일치 여부가 불분명한 곡은 가사 없음으로 표시합니다.
가사가 없는 상태와 제공처 장애·시간 초과·호출 제한은 구분합니다.
곡 검색이 비어 있으면 MusicBrainz의 가수 별칭을 조회해 가수 ID로 다시 검색합니다.
예: 리도어 → Redoor. 임의 번역이나 특정 가수의 이름 하드코딩은 사용하지 않습니다.
가사도 제공처에서 확인한 별칭의 한글·영문 병기를 대조합니다. 가사 조회 중에는 MusicBrainz를 호출하지 않고 이미 확보한 별칭만 사용합니다.
다만 제공처에 별칭이 없거나 곡의 한글 제목 자체가 등록되지 않았다면 누락될 수 있습니다.
LRCLIB는 이용자 등록 자료이므로 정확성이나 모든 한국어 곡의 제공을 보장하지 않습니다.

요청에 프로젝트 User-Agent를 명시합니다. 성공한 공개 응답은 24시간 디스크에 캐시하고,
장애 때 7일 이내 기존 응답을 표시할 경우 이를 화면에서 알립니다. 빈 결과·404는 5분입니다.
저장된 곡·가사는 DB로 열며, 가사 새로 확인 버튼을 눌렀을 때만 갱신합니다.
프로세스 간 호출 임대·간격·대기 상태는 SQLite로 공유합니다. 429/503은 즉시 재시도하지 않습니다.
네트워크 오류 등은 최대 한 번 재시도하며, 외부 조회 예산은 요청당 18초입니다.
캐시가 없는 첫 검색의 제공처 장애까지 없앨 수는 없습니다. 실패와 가사 없음은 구분합니다.

오픈소스 서버의 코드 라이선스와 음악·가사 콘텐츠의 이용 권한은 별개입니다.
출처 정보는 내부 데이터와 개발 문서에 보관하며, 서비스 화면의 출처 문구·링크는 표시하지 않습니다.
콘텐츠를 별도의 공개 데이터셋으로 배포하지 않습니다.
크롤링·음원 스트리밍·다운로드는 구현하지 않습니다.
앨범 표지는 Cover Art Archive에서 API 키 없이 가져와 홈 카드·곡 상세·저장된 음악 선택창에 표시합니다.
발매 ID로 승인된 앞표지를 확인하고, 없으면 MusicBrainz가 확인한 같은 앨범 그룹의 대표 표지를 사용합니다.
화면이 열린 뒤 별도로 조회하며 원래 URL은 `Album.image`에 저장합니다. 확보한 표지는 로컬 파일로도 보관합니다. 화면에는 표지만 표시합니다.
빈 결과는 5분 캐시하고 장애 시 최소 60초 동안 재요청을 막습니다.
표지 다운로드 오류·12초 초과 시 기본 이미지로 돌아갑니다. 표지가 없는 곡도 기록할 수 있습니다.
저장한 곡은 홈과 곡 상세의 북마크를 초록색으로 채워 표시하고, 저장 취소 시 윤곽선으로 돌아갑니다.
Gemini 추천은 계속 보류 상태입니다.

## 외부 조회 안정화

홈의 음악 검색·가사·평론·표지는 서버의 작은 작업 대기열에서 처리합니다.
Flask와 표준 라이브러리 스레드 2개, SQLite를 사용하며 추가 서비스 설치는 필요하지 않습니다.
화면은 먼저 열리고 자료가 준비되면 갱신됩니다. 같은 곡의 같은 요청은 계정·브라우저가 달라도 작업을 공유합니다.
작성 중인 감상과 계정 데이터는 대기열에 넣지 않습니다. 기존 동기 API도 유지합니다.

- 가사: DB → 이전에 확인한 가사 ID → 곡·가수·앨범·재생시간 직접 조회 → 검색 순서입니다.
  확인된 한글·영문 제목만 사용하고, 다른 버전·가수·재생시간 검사를 계속 적용합니다.
  LRCLIB는 기본 1.05초 간격으로 호출합니다. 선택적인 서버 키는 `LRCLIB_API_KEY`입니다.
- 검색: 저장된 검색 결과를 즉시 표시합니다. 유효 기간이 지난 결과는 이전 자료임을 알리고 뒤에서 갱신합니다.
  빈 검색 결과는 5분만 보관합니다. 이전 검색이 늦게 끝나도 새 검색 화면을 덮지 않습니다.
  외부 검색 실패는 알리고, 별도 제목 아래 저장된 음악을 바로 열 수 있게 표시합니다.
- 대기열: 최대 128개 대기 작업과 완료 결과 256개를 보관합니다. 가사를 우선 처리합니다.
  일시 실패는 제공처 대기 시간을 지켜 한 번 추가 시도합니다. 장시간 호출 제한은 기다릴 시간을 안내합니다.
  중단된 작업은 임대 만료 후 이어 처리하며, 반복 중단은 실패 상태로 바꿔 무한 로딩을 막습니다.
- 표지: 확인된 제공처의 HTTPS 이미지에 한해 형식과 최대 2MB를 검사하고 원자적으로 저장합니다.
  표지 파일은 최대 128개·32MB로 제한합니다. 확보한 파일은 외부 서버가 느려도 로컬에서 표시합니다.
  실제 가사와 코멘트는 표지 캐시 정리의 영향을 받지 않습니다.

공개 자료 캐시와 대기열·표지 파일은 `instance/` 아래에 생성되고 Git에는 포함되지 않습니다.
자료가 없는 경우와 외부 연결 실패는 계속 구분합니다. 모든 곡의 자료가 제공되는 것은 아닙니다.

시연 전에 **이미 등록된 곡**의 준비 상태를 확인하거나 부족한 자료를 확보할 수 있습니다.
개인 음악 기록·별점·저장 여부·코멘트는 추가하지 않습니다.

```sh
python -m scripts.prepare_catalog
python -m scripts.prepare_catalog --fetch --song-id 5
python -m scripts.prepare_catalog --fetch --limit 10
```

실제 가사·평론·표지와 두 계정의 작업 공유, 새 프로세스에서 외부 HTTP 없이 재사용되는지 확인하려면:

```sh
python -m scripts.verify_resource_pipeline
```

이 검사는 임시 DB를 사용합니다. `--serve`를 붙이면 검증 후 별도 브라우저 시험 서버가 5003번 포트에서 열립니다.

## 실제 평론 연결

곡 상세를 열면 IZM의 공개 검색 응답에서 관련 리뷰를 별도로 찾습니다. API 키가 필요하지 않습니다.
적합한 리뷰가 없으면 HELLOKPOP의 공개 API에서도 연말 결산 선정 항목을 찾습니다.
음악·가사 화면을 먼저 열고 평론 조회를 진행하므로 작성 중인 감상을 지우거나 기다리게 하지 않습니다.
싱글 리뷰는 가수·곡명, 앨범 리뷰는 가수·앨범명이 일치할 때 연결합니다.
다른 앨범 리뷰라도 실제 수록곡 목록에 같은 곡이 명시된 경우에는 **수록 앨범 평론**으로 구분합니다.
단순 본문 언급이나 같은 가수라는 이유로 연결하지 않으며 라이브·반주·리믹스 표기는 구분합니다.
영문 가수의 한글 별칭은 해당 곡의 MusicBrainz 가수 ID로 확인하며, 동명이인 검색 결과를 합치지 않습니다.

평론 전문을 화면이나 DB에 복사하지 않습니다. 공개 검색 응답의 HTML은 Beautiful Soup으로 읽고,
작성자·제목·원문 URL·수록곡 및 최대 한 문장(20어절·110자)의 짧은 발췌만 캐시에 보관합니다.
소개용 문구를 평론가의 말처럼 새로 만들지 않습니다. 평론 원문은 별도 탭에서 읽을 수 있습니다.
제공처 이름은 화면에서 숨기고 내부에 보관합니다. 오픈소스는 파서 코드이며 IZM 글 자체가 오픈소스인 것은 아닙니다.

성공한 평론은 SQLite에 저장해 다음 조회에서 바로 표시합니다. 없는 결과는 5분, 일시 오류는 최소 60초 재요청을 막습니다.
저장된 한 평론을 여러 관련 곡에 연결해도 글 자체를 중복 저장하지 않습니다.
확인된 자료가 없으면 **등록된 평론·선정글 없음**, 조회 장애는 별도 안내를 표시합니다.
IZM 검색은 공개 사이트가 사용하는 경로로, 사이트 구조 변경이나 제공처 장애 시 조회가 실패할 수 있습니다.
가수의 다른 이름을 확인하면 앞서 받은 곡명·앨범명 검색 결과도 다시 검사해 관련 리뷰가 누락되지 않도록 합니다.
확인하지 못한 사이트의 제한을 우회하거나 전문을 대량 수집하지 않습니다.

임시 DB에서 검증했습니다. 사용 중인 브라우저에서는 잔나비 곡 상세에 Monkey Hotel(임진모)의
앨범 평론이 표시되는 것을 확인했습니다. 리도어 Hospital의 적합한 평론은 아직 찾지 못했습니다.

## 추가 API

- `GET /api/catalog/search?q=밤편지&page=1`: 외부 음악 검색
- `POST /api/catalog/import`: `{ "external_id": "MusicBrainz recording UUID" }`
- `GET /api/home?page=1`: 내 음악 기록 카드·통계
- `POST /api/songs/<곡ID>/lyrics`: 저장된 가사 우선 사용, `{refresh:true}`이면 제공처 조회
- `GET /api/songs/<곡ID>/comments`: 현재 권한으로 볼 수 있는 구절 코멘트

외부 실패는 `provider_error`, `provider_timeout`, `provider_rate_limited`,
`provider_busy` 코드로 반환합니다. AI 추천 성공이나 빈 검색 결과로 위장하지 않습니다.

## 한글·영문 곡명 연결

1. 원래 곡명과 가수로 LRCLIB를 검색합니다.
2. 검색되지 않으면 같은 MusicBrainz 곡 ID의 별칭과, 출처를 확인해 등록한 다른 제목을 사용합니다.
3. 다른 제목으로 연결할 때에는 가수·앨범·재생시간(±2초)이 일치해야 합니다.
4. 확인된 다른 제목이 없으면 같은 가수·앨범·재생시간의 가사를 **후보**로만 표시합니다.
   후보가 하나여도 자동 연결하지 않습니다. 제목과 미리보기를 확인하고 연결 버튼을 눌러야 저장합니다.

`backend/data/title_aliases.json`은 공식 자료에서 확인한 제목 대응을 기록하는 작은 파일입니다.

MusicBrainz 곡 ID·원래 제목·가수·앨범·재생시간에 한정해 적용합니다.
임의 번역이나 재생시간만으로 모든 곡의 제목을 추측하지 않습니다.
다른 제목으로 연결한 사실과 사용자 확인 여부는 가사 화면에 표시하고 DB에 남깁니다.

## 가사 없음과 조회 오류 구분

- `available`: DB에 가사가 저장되어 있음. 기본 조회는 외부 API를 호출하지 않습니다.
- `unqueried`: 아직 조회하지 않음. 가사가 없다고 판단한 상태가 아닙니다.
- `instrumental`: `(instrumental)`, `(Inst.)` 등 반주 버전. 조회를 생략하고 보컬 버전 선택을 안내합니다.
- `unmatched`: 제목이 다른 가사 후보가 있음. 사용자 확인 전에는 연결하지 않습니다.
- `missing`: 제공처에서 일치 결과를 찾지 못함. 미등록 또는 표기 차이일 수 있으며, 곡에 원래 가사가 없다는 뜻이 아닙니다.
- `error`: 시간 초과·호출 제한 등 일시적 조회 실패. 대기 시간을 표시하고 중복 재요청을 막습니다.

`instance/preview.db`의 `lyric_lookup` 테이블에 최근 조회 상태와 재시도 시간을 저장합니다.
확인된 빈 결과는 5분 재사용하며 수동 갱신이 가능합니다. 장애의 대기 시간은 수동 갱신에도 적용합니다.
갱신이 실패하더라도 기존 가사와 코멘트는 유지하고 `refresh_failed`와 안내 문구를 반환합니다.

후보 검색은 LRCLIB에 필요한 `q`를 포함합니다. 이전의 가수·앨범만 보내던 요청은 빈 결과를 유발해 수정했습니다.

### 가사 검색 병기·선택 개선

`JANNABI(잔나비)`처럼 한글·영문을 괄호로 병기한 이름을 양방향으로 인식합니다.
가수명 일부가 같거나 `feat.`로 참여한 경우를 같은 가수로 간주하지 않습니다.
가수 필터 검색이 비면 곡명만으로 다시 검색하고, 가수·제목·버전·재생시간 검증은 유지합니다.
여러 결과가 있으면 앨범 일치와 재생시간 차이를 비교해 선택합니다. 잘못 등록된 재생시간은 제외합니다.
반주·라이브·커버·느린 버전 등은 원곡과 구분합니다. 동기화 가사는 시간 태그만 제거하고 실제 대괄호 가사는 보존합니다.

가사가 아직 저장되지 않은 곡은 상세를 열 때 자동 조회합니다. 최근 실패·빈 결과의 대기 시간 중에는
자동 조회와 반복 클릭을 막으며, 제목이 다른 후보는 사용자 확인을 거칩니다.
이미 저장한 가사와 구절 코멘트는 계속 사용하고 새 버전으로 덮어쓰지 않습니다.
가사 처리에는 MusicBrainz HTTP가 필요하지 않습니다. 다른 화면에서 확인해 둔 가수 별칭이 있으면 캐시로만 읽습니다.
